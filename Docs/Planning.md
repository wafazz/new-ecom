## 2. Stack and Rules
- PHP 8.2+, no framework, hand-written MVC, PDO (MySQL/MariaDB).
- Own `.env` loader (no Composer dependency). `.env` git-ignored, `.env.example` committed.
- Single front controller `public/index.php`; only `public/` is web-exposed.
- Security from day one: prepared statements, `password_hash`, CSRF, output escaping, hardened sessions, upload validation, role middleware.

## 5. Product Management (R7, R8, R9)
**Price fields (ASSUMPTION, pending confirmation Q1):**
- `base_price` = supplier cost, admin-only.
- `company_base_price` = company internal floor price; used for margin/commission; hidden from members.
- `retail_price` = public list price.
- `discount_price` = optional promo price, optional `discount_start` / `discount_end`.
- Selling price = active `discount_price` if set, else `retail_price`.
- Validation: `discount_price <= retail_price` and `retail_price >= company_base_price >= base_price`.

**Variations:**
- `product_options` (Size, Color) -> `product_option_values` (S, M, Red) -> `product_variants` (SKU, stock, 4 prices, image; blank price = inherit from product) linked via `variant_option_values`.

**CRUD:** search/filter/pagination; add, edit, soft-delete (keeps order history); image upload validated by MIME, size, random filename.

## 6. Checkout (R10, R11)  [added rev 2]
Two modes, one `CheckoutService`, one flow.

| Aspect | Logged-in member | Guest |
|---|---|---|
| Identity | `orders.user_id` set | `orders.user_id` NULL; `guest_email`, `guest_name`, `guest_phone` stored on order |
| Cart | `carts.user_id` | `carts.session_id` (cookie) |
| Address | Pick saved address or add new | Enter on form; stored as snapshot on order |
| Login at checkout | n/a | "Log in" link on checkout page; guest cart merges into member cart on login |
| Optional account | n/a | Checkbox "Create account" -> creates member after order (password set, email verified) |
| Order tracking | Member portal | Tracking link by `order_no` + email (signed token), no login needed |
| Affiliate attribution | Cookie `ref` applied | Cookie `ref` applied |

Rules:
- Guest cart in DB keyed by session id; expires after 7 days (cleanup job).
- Guest email matching an existing member: prompt to log in, but do not block checkout.
- Self-referral blocked: affiliate's own user id / email cannot earn commission on own order.
- Order stores full address, price and product-name snapshots so later edits do not change history.
- Rate-limit guest order creation and order lookup (anti-abuse). CSRF on all checkout posts.
- Settings flag `guest_checkout_enabled` (default on) so admin can toggle it.

## 7. Affiliate URL (R6)
- Member gets unique `affiliate_code`. Link: `/r/ABC123` or `/product/slug?ref=ABC123`.
- `/r/{code}`: log click in `affiliate_clicks` (IP hash, UA), set 30-day `ref` cookie (configurable), redirect.
- Checkout fills `orders.affiliate_id` from cookie (member and guest).
- On order completed: `affiliate_commissions` row `pending` -> `approved` -> `paid`.
- Commission basis (pending Q3): % of selling price, % of margin (`selling - company_base_price`), or fixed per product.
- Admin approves commissions and records payouts; member sees stats.

Billplz checkout (2026-10-22, API checked against support.billplz.com/api): method `billplz` is offered at checkout only when credentials are saved AND the last 'Test connection' passed (any credential change hides it until re-tested). Flow: order is placed first (pending/unpaid, stock held) -> `BillplzGateway::start()` creates ONE bill per order (row-locked; amount = order total in cents, email, +60 mobile, order no. as reference_1, callback_url, redirect_url) -> customer is redirected to the Billplz page (CSP form-action allows Billplz origins, Chrome applies it to the redirect). If Billplz is down the order is kept and the order page offers 'Pay now' (reuses the same bill, rate limited, CSRF + ownership/token checked). `POST /payments/billplz/callback` (outside the CSRF group, authenticated only by X-Signature): HMAC-SHA256 over sorted `key+value` pairs joined by `|`, constant-time compare; then the bill must exist, collection must match, `amount` must equal OUR order total and `paid_amount` must cover it; only then `OrderService::recordPayment()` (idempotent). Always answers 200 for validly signed but irrelevant callbacks so Billplz stops retrying; 403 for bad signatures. `GET /payments/billplz/return`: signed redirect, then confirmed server-side with GET /v3/bills/{id} (state paid + amount) before marking paid; members land on their order page, guests see a result page that shows the order number only (their secret order link is never sent to Billplz). Money arriving for an already-cancelled order is recorded as paid + event 'paid_after_cancel ... REFUND NEEDED'; the admin dashboard counts these ('Refunds needed') and the order page shows a refund warning. `bin/expire-unpaid.php` (cron hourly) cancels unpaid Billplz orders after UNPAID_HOLD_HOURS (default 24) and restocks. Migration 020 adds orders.billplz_bill_id (UNIQUE) and billplz_url. Verified: 20 signature/URL unit checks (vectors computed with openssl), payment DB checks, and 45 HTTP checks against a local Billplz stub.
